## v2.11.358 — 심층 리서치 1단계: 자료를 두 배로 모으고, 숫자·날짜를 자료끼리 대조

### 바뀐 점
- **자료 수집 폭 2배(A1).** 앱에서 글을 생성할 때 모으는 기사·글이 최대 8건·20,000자 → **16건·40,000자**로 늘었습니다(후보 풀 18 → 26건, 수집 시간 예산 20초 → 45초). 첫 검색 상위 몇 건에만 있던 사실 때문에 글이 얕아지던 구조를 넓혔습니다. 설계도(1회 호출)에 들어가는 재료 상한도 30,000 → 45,000자. 화면이 실시간 수집을 기다리는 상한도 30초 → 60초로 맞췄습니다(짧으면 모은 자료가 통째로 버려짐). **본문 호출 프롬프트 크기는 그대로**(설계도가 재료를 압축해 넘기므로).
- **숫자·날짜 교차 검증(A2, 모델 호출 없음).** 리서치 요약의 수치·날짜마다 다른 자료에도 같은 값이 있는지 세어 "✔ 자료 N건 일치" 또는 "⚠ 단일 출처"를 붙이고, 단일 출처 수치는 "A 자료 기준"처럼 출처를 밝혀 쓰고 단정하지 말라는 지시를 요약 머리에 넣었습니다. 요약 머리에 "확인된 사실 M · 단일 출처 K"가 표시됩니다.

### 확인한 사실
- 비용: 설계도 입력이 편당 최대 약 15,000자(≈8,000 토큰) 늘 수 있고, 본문 호출은 변화 없습니다. 실측 비용은 다음 생성 로그로 봅니다.
- 시간: 수집이 순차라 생성 시작이 최대 25초 늦어질 수 있습니다(예산 45초 안에서 모은 만큼만 씁니다).
- 품질 변화는 저장된 글·하네스로 전/후 비교할 예정이며, 이번 릴리즈 노트에는 추정 효과를 적지 않습니다.
