# 공개 시각 기준 예약·캡처 전달 — 2026-10-21

이 문서는 과거 임시저장 기본/작업 시작 시각 설명보다 최신인 사용자 결정을 기록한다. 앞으로 만드는 허용 3계정의 새 글은 선택한 한국시간에 네이버에서 공개되도록 예약한다. 09:00 공개는08:00 조사·작성·이미지 준비, 00:30 공개는 전날23:30 준비다. 준비 시작 시각에 즉시 공개하지 않는다. 기존 공개/예약/임시저장 글과 앱에 저장된 기존 draft/publish 계획을 자동 전환하지 않는다.

기본 완전 자동 경로는 Codex/Claude Code의 Chrome 직접 작업이다. 자동화앱은 반자동 원고 전달·이미지 관리·검토 경로로 사용한다. 앱의 새 정기 예약 경로는 별도의 기능 지원과 실제 예약 검증 연결이 필요하며 Chrome 직접 작업이 앱에 이미 내장됐다고 설명하지 않는다.

## 앱·확장 소스 계약

- 새 화면 기본 계획은 `mode:'schedule', leadMinutes:60`. 슬롯 시각은 공개 예정 시각이다. 기존 draft/publish 슬롯은 작업 시작 시각 의미를 유지한다.
- 스케줄러는 준비 시각에만 새 작업을 만들며, 키는 공개 날짜·공개 시각·계정·순번이다. `prepareAt`과 `scheduledFor`는 별도 UTC ISO 값이다. 앱은 준비 분을 놓친 작업을 몰아서 실행하지 않는다.
- 상태의 `nextAt`은 다음 준비 시작, `nextScheduledFor`는 다음 공개 예정이다. 이전 앱에 명시적 scheduling 지원이 없으면 새 예약 저장/실행을 막고 기존 중지는 유지한다.
- 실행은 `scheduleType:'naver-server'`, KST `scheduleDate`/`scheduleTime`으로 전달한다. 유료 생성 전과 최종 제출 전에 같은 목표 시각을 확인한다. 마감 경과는 보류하며 즉시 공개나 다음날 목표로 바꾸지 않는다.
- 완료는 실제 네이버 예약 목록에서 대상 블로그·카테고리·제목·날짜·시각을 확인한 결과만 인정한다. 공개 URL·임시저장·제출 버튼·`APP_SCHEDULE_QUEUED`는 예약 확인 증거가 아니다.

현재 실제 예약 목록 어댑터가 연결되지 않은 앱 경로는 생성/브라우저 작업 전에 명시적으로 보류한다. 소스·계약 테스트가 통과해도 해당 설치 앱에서 새 예약이 가능하다고 안내하지 않는다. 라이선스 제한과 기존 보호 정책도 우회하지 않는다.
상태 API는 `scheduling.nativeReservationReady:false`로 이 준비 상태를 따로 알린다. 이 상태에서는 예약 계획을 중지 상태로 저장하거나 기존 계획을 중지할 수 있지만 새 예약 실행 시작은 422 `DAILY_NATIVE_RESERVATION_ADAPTER_REQUIRED`로 거부한다.

## 실제 캡처와 이미지 관리→타이핑

`official-capture`와 `ai-generated`는 분리한다. 공식 캡처 소비기는 운영자가 별도 검토한 `daily-official-sources.json`과 작업/계정/분야/최종 소제목에 맞춘 실제 파일 묶음을 읽는다. 누락은 PENDING, 증빙·파일·권리·매핑 불일치는 REVIEW로 보류한다. 이 소비기는 직접 캡처·검색·AI 생성·발행하지 않는다. JSON의 verified 표시나 출처 한 줄이 실제 캡처·이용 허락의 자동 증명이 아니다.

반자동 이미지 전달은 실제 래스터의 MIME·픽셀 디코딩·해시를 확인하고 원본 바이트를 앱 저장소에 보존한다. 캡션·출처 URL·수집 표시·오버레이 방지·원고ID·해시가 import→ImageManager→그리드→재불러오기→타이핑 payload에 이어진다. 임의 officialVerified/권리 승인 필드를 전달받아 신뢰하지 않는다. 수집 이미지는 전체 프레임으로 미리 보고, 다른 원고의 수집 이미지를 섞지 않는다.
