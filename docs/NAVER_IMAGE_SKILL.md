## 2. 규격

- 플랫폼 값이 없으면 **NAVER**다. 썸네일과 소제목 이미지 모두 **800x800(1:1)**이다.
- 사용자가 크기를 주면 그 값을 쓴다. 외부 자동화가 GOOGLE 등 다른 플랫폼을 주면 그 플랫폼의 기존 설정을 따른다.
- 한 글의 이미지 세트는 같은 규격을 유지한다. 특별한 이유가 있을 때만 바꾼다.
- NAVER인지 GOOGLE인지 다시 묻지 않는다.
- NAVER 썸네일을 16:9로 만드는 것은 금지다.

## 3. 입력 유형과 처리

| 유형 | 예 | 처리 | 질문 |
|---|---|---|---|
| A. 제목 + 전체 소제목 | 글 전체를 붙여 넣음 | 썸네일 + 소제목 이미지 세트 전체를 설계 | 없음 |
| B. 제목 + 현재 소제목 | "2번 소제목 이미지" | 그 소제목 이미지만 생성. 다른 소제목을 알면 역할이 겹치지 않게 | 없음 |
| C. 제목만 + 썸네일 | "썸네일 만들어줘" | 제목 분석 → 핵심 엔티티 → CARD_PROMISE → 실제 자산 필요 여부 → 자료 확인 → 생성 | 소제목을 요구하지 않는다 |
| D. 제목만 + 소제목 이미지 | "소제목 이미지 만들어줘" | 소제목이 없을 때만 질문 | "이미지로 만들 소제목을 보내주세요." 한 줄 |
| E. 번호 지정 | "3번 이미지", "4번 다시" | 그 번호로 바로 이동 | 없음 |

이미 받은 값은 다시 묻지 않는다: 플랫폼, 제목, 소제목, 이미지 방향, 텍스트 설정, 참조 이미지, 기사 URL, 출처 URL, 이전 이미지 정보.

## 4. CARD_PROMISE 만들기

정의: **이 제목을 보고 독자가 클릭하는 가장 직접적인 이유 한 문장.** 썸네일을 만들기 전에 반드시 내부적으로 만든다.

만드는 순서:
1. 제목에서 핵심 엔티티를 찾는다. 사람, 제품, 장소, 제도, 숫자가 후보다.
2. 독자가 얻는 것을 찾는다. 금액, 차이, 결과, 반전, 관계, 방법이 후보다.
3. 둘을 한 문장으로 잇는다. 제목에 없는 사실은 넣지 않는다.

| 제목 | CARD_PROMISE |
|---|---|
| EV3 실구매가, 보조금 빼니 334만원 차이 | 보조금 적용 후 두 트림의 실구매가 차이는 334만원 |
| 소희 양말 신던 중학생이었다…박서함 팬심 고백에 담긴 기억 | 박서함이 중학생 때 안소희 팬이라 '소희 양말'까지 신었다고 고백 |
| 청년월세 20만원 받는 법 | 조건을 맞추면 월 20만원을 받을 수 있다 |
| 제주 유채꽃 축제, 주차와 셔틀버스 이용법 | 축제장 주차와 셔틀 이용 방법을 한 번에 |

실패 판정: 썸네일이 CARD_PROMISE와 다른 후킹을 만들면 실패다. 예를 들어 제목은 가격 차이인데 썸네일은 "충격 반전"이면 실패다. 제목, 썸네일, 본문 첫 화면은 같은 약속을 가리켜야 한다.

## 5. REAL ASSET RESOLVER

### 5.1 우선순위

1. 사용자가 직접 첨부한 실제 이미지
2. 사용자가 제공한 실제 이미지 URL
3. 기사·공식페이지·출처 URL에 연결된 실제 이미지
4. 검색으로 확인한 실제 대상의 이미지·외형·장면
5. 정보그래픽·비교·절차 같은 AI 시각화
6. 적절한 실제 자료가 없을 때만 순수 AI 생성

### 5.2 REAL 우선 주제

연예, 방송, 스포츠, 자동차, 실제 제품, 여행지, 축제, 사건·현장, 실제 건물·시설. 이 주제에서는 실제 자료부터 확인한다. 실제 자료가 없을 때만 5~6단계로 내려간다.

### 5.3 자산 분류

| 분류 | 정의 | 직접 합성 | 예 |
|---|---|---|---|
| USER_ASSET | 사용자가 직접 제공한 이미지 | 가능 | 업로드한 사진, 내 폴더 사진, 사용자가 본문에 직접 넣은 사진 |
| SOURCE_ASSET | 기사·공식자료에서 확인한 이미지 | 사용자가 본문에 쓰기로 한 것만 | 사용자가 동의하고 수집해 본문에 넣은 기사·공식 이미지 |
| REFERENCE_ONLY | 실물 특징 참고용. 직접 합성하지 않는다 | 불가 | 기사 URL, 검색 결과, 권리 불확실한 이미지 |
| AI_ASSET | AI가 생성한 이미지 | 해당 없음 | 생성 엔진 결과 |
| INFOGRAPHIC | 비교표·절차·개념 시각화 | 해당 없음 | 비교표, 체크리스트 카드 |

이미지마다 출처(provenance)를 기록한다. 어디서 왔는지, 누가 넣었는지, AI인지를 남긴다.

### 5.4 권리 판단

- 실제 이미지 URL을 찾았다고 사용 권한이 생기지 않는다.
- 출처를 표시해도 재사용 권리가 생기지 않는다.
- 실존 유명인의 사진은 초상권·퍼블리시티권·사진 저작권이 함께 걸린다. AI로 만든 닮은꼴도 같은 문제가 된다(SPEC-IMAGE-PORTRAIT-2026 참고).
- 권리가 불확실하면 REFERENCE_ONLY로 처리한다. 실제 모습 확인에만 쓴다.
- 필요하면 업로드를 요청한다: "실제 사진을 올려 주시면 그 사진으로 썸네일을 만들게요."
- 사용자가 직접 올리거나 본문에 넣기로 한 사진만 합성 재료가 된다. 그 사진의 게시 판단은 사용자 몫이고, 도구는 권리를 보증하지 않는다.

### 5.5 판단 순서

```
REAL 우선 주제인가?
├─ 아니오 → 정보형/AI 계획으로 (§8, §19)
└─ 예 → 합성 가능한 실제 사진(USER_ASSET, 쓰기로 한 SOURCE_ASSET)이 있는가?
        ├─ 있음 → 실제 사진 합성형 썸네일 (§7). AI 생성 호출을 생략한다.
        └─ 없음 → URL·검색 결과만 있는가?
                ├─ 있음 → REFERENCE_ONLY. 외형은 참고만 한다. 업로드를 안내한다.
                └─ 없음 → 정직한 상징형 AI 구성 (§6.3)
```

## 6. 실존 인물 · 연예 · 이슈

### 6.1 우선 구성

실제 핵심 인물 + 실제 상대 인물·대상 + 기사 핵심 맥락

| 기사 | 구성 |
|---|---|
| 팬심 고백 | 실제 박서함 + 실제 안소희 + 팬심·과거 기억 암시(양말은 보조) |
| 웨딩 이슈 | 실제 두 인물 + 웨딩 관련 실제 맥락 |
| 발언 기사 | 실제 발언 인물 + 발언 상황 또는 핵심 상대 |
| 방송 장면 | 실제 프로그램·출연자 이미지 우선 |

### 6.2 금지에 가까운 방향

- 실제 박서함 기사에 박서함과 닮지 않은 임의 AI 남성
- 실제 배우 기사에 무관한 AI 모델
- 실제 방송 기사에 기사와 관계없는 영화 같은 재연 장면
- 확인되지 않은 사건·감정의 재연

### 6.3 실제 사진이 없을 때: 정직한 상징형

인물을 AI로 재현하지 않는다. 닮은꼴도 만들지 않는다. 대신 다음으로 구성한다.
- 사건의 사물: 양말, 음반, 팬굿즈, 판결문처럼 기사에 나온 물건
- 장소: 방송국 로비, 법원 외관처럼 기사에 나온 곳
- 숫자나 짧은 문구
- 사람이 꼭 필요하면 작게, 뒷모습으로, 식별할 수 없게

## 7. 실제 이미지 합성

사용자가 실제 이미지를 1장 이상 주면 특별한 이유가 없는 한 그것을 쓴다.

허용 방향:
- 실제 인물 2인 합성
- 실제 피사체 크롭
- 배경 교체·확장, 여백 생성
- 텍스트 배치, 자연스러운 그래픽 요소 추가
- 실제 피사체 + AI 보조 배경
- 2장 이상의 편집형 구성

목표는 사진을 붙이는 것이 아니다. **실제성 + CARD_PROMISE + 모바일 가독성**을 함께 만족하는 새 썸네일이다.

피할 것:
- 과도한 콜라주
- 조명·해상도가 어긋난 채 드러나는 조잡한 합성
- 인물 얼굴 왜곡

두 사람 기사: 실제 사진이 두 장 있으면 한 장씩 같은 크기로 잘라 좌우에 나란히 놓는다. 사이에 얇은 밝은 틈을 둬서 한 장처럼 속이지 않는다. 짧은 문구는 사진 아래 별도 띠에 넣어 얼굴을 가리지 않는다. 비교 제목(두 제품, 두 금액)도 같은 방식이다. 그 밖의 글은 한 장이 작게 봐도 더 잘 읽힌다.

크롭 규칙(얼굴 인식 없이):
- 칸보다 세로로 긴 사진은 위쪽을 남긴다. 얼굴과 상체가 보통 위에 있다.
- 그 밖의 사진은 가장 눈에 띄는 영역(피부색·채도·밝기)을 기준으로 옆을 자른다. 한쪽에 치우친 인물도 화면에 남는다. 눈에 띄는 것이 없으면 가운데를 자른다.
- 칸을 채우려면 2.2배 넘게 키워야 하는 작은 사진은 쓰지 않는다. 짧은 변이 300px 미만인 사진과 읽을 수 없는 사진은 합성 재료에서 뺀다.
- 두 장 합성이 실패하면 한 장 합성으로, 첫 사진이 안 되면 두 번째 사진으로, 실제 사진이 전부 안 되면 AI 표지로 간다. 합성 실패 때문에 썸네일 생성 전체가 실패하지 않는다.
- 두 사람의 얼굴 크기는 원본 사진의 구도에 따라 달라질 수 있다. 얼굴을 찾아 크기를 맞추지는 않는다.

## 8. 썸네일 전략

썸네일은 글 전체를 요약하지 않는다. **가장 강한 클릭 이유 하나**만 보여준다.

클릭 이유 후보: 실제 인물, 핵심 숫자, 가격 차이, 관계, 결과, 반전, 비교, 문제 상황, 제품, 장소, 변화.

### 8.1 방향 4가지

| 방향 | 언제 | 어떻게 |
|---|---|---|
| 비교 | 제목에 차이·비교·대비·vs, 또는 금액이 두 개 | 비교 대상 둘을 같은 크기로 나란히 놓아 차이가 한눈에 보이게 |
| 숫자 | 금액·%·기간·개수가 핵심 | 숫자 뒤의 실물(서류, 고지서, 세어지는 물건)을 보여준다. 숫자 자체는 문구로 넣는다 |
| 문제 장면 | 논란·피해·사고·사기·거절 등 | 잘못된 순간이나 긴장된 현장을 평이하게. 얼굴은 프레임 밖 |
| 실제 재구성 | 위에 해당하지 않음 | 제목이 약속하는 상황을 연출 없는 실제 사진처럼 |

### 8.2 필수 조건 (소제목 이미지보다 엄격하게)

- 800x800
- 휴대폰 피드에서 약 200px 폭으로 보인다고 가정한다. 그 크기에서 핵심 대상이 식별돼야 한다
- 주요 대상은 1~2개
- 배경 과밀 금지, 과한 포스터 연출 금지, 불필요한 소품 금지
- 긴 제목 복사 금지

## 9. 썸네일 텍스트

### 9.1 모드

| 모드 | 동작 |
|---|---|
| AUTO(기본) | 아래 표로 넣을지 판단한다 |
| 포함 | 짧은 문구를 넣는다. 제목 전체는 넣지 않는다 |
| 미포함 | 문구를 넣지 않는다 |

AUTO 판단:

| 상황 | 결정 |
|---|---|
| 핵심 숫자·가격 차이·마감·기간이 있음 | 넣는다 |
| 짧은 발언(따옴표)이 있음 | 넣는다 |
| 비교 결과·짧은 질문 | 넣는다 |
| 제품 외형 자체가 핵심이고 숫자가 없음 | 뺀다 |
| 여행 장소 자체가 강하고 숫자가 없음 | 뺀다 |
| 텍스트가 실제 피사체를 가림 | 뺀다 |
| 그 밖의 이슈형 제목 | 짧은 핵심 문구를 넣는다 |

### 9.2 문구 만드는 순서

1. 제목에 숫자 구절이 있으면 그것을 쓴다. 연도만 있는 숫자는 제외한다. 예: "334만원 차이", "징역 10년 구형"
2. 따옴표 발언이 있으면 그것을 쓴다. 예: "소희 양말도 신었어요"
3. 없으면 첫 의미 덩어리를 쓴다. 끝이 "~던", "~는"처럼 걸리는 말로 끝나면 떼어낸다

제한:
- 핵심 엔티티 + 클릭 이유
- 1~2개 의미 덩어리, 최대 2~3줄, 대략 16자 안쪽
- 제목에 있는 단어만 쓴다. 글에 없는 주장을 만들지 않는다

| 제목 | X | O |
|---|---|---|
| 소희 양말 신던 중학생이었다…박서함 팬심 고백에 담긴 기억 | 제목 전체 | "중학생 때 / 소희 양말" 또는 "소희 양말도 신었어요" |
| EV3 실구매가, 보조금 빼니 334만원 차이 | 제목 전체 | "334만원 차이" |
| 청년월세 20만원 받는 법 | - | "청년월세 20만원 받는 법"(이미 짧음) |

### 9.3 한글 오류

오타, 깨진 글자, 숫자 오류가 있으면 미완성이다. 자동 승인하지 않는다.

누가 문구를 그리는가(2026-09-23 사장님 결정):

| 엔진 | 문구 |
|---|---|
| 나노바나나2, 나노바나나 프로, Flow, GPT 이미지(덕트테이프), 리더스 나노바나나 | 엔진이 짧은 문구를 직접 그린다. 앱은 따로 얹지 않는다 |
| 나노바나나 2.5(엔진 목록에 "한글 텍스트 깨짐"), Leonardo, DeepInfra, Prodia, ImageFX | 엔진에는 글자 없는 이미지를 요청하고, 앱이 짧은 문구를 한 번 얹는다 |
| 실제 사진 합성 | 앱이 짧은 문구를 얹는다(두 장이면 아래 띠) |

## 10. 후보 전략과 심사

한 방향을 맹목적으로 생성하지 않는다. 내부적으로 최소 2개 방향을 비교한 뒤 고른다.
- A. 실제 사진 합성(REAL_IMAGE_COMPOSITE)
- B. 실제 사진 + 그래픽(REAL_IMAGE + GRAPHIC)
- C. AI 또는 정보그래픽 대안

생성 장수는 비용 설정을 따른다.

| 모드 | 장수 | 심사 |
|---|---|---|
| 기본 | 1장 | 없음 |
| 고품질 | 2~3개 후보 | 1회, 가장 적합한 1개 추천 |

사용자 요청 없이 비용이 크게 늘어나는 다중 생성을 기본으로 강제하지 않는다.

심사 기준(각 1~5점):
- meaning: 제목·CARD_PROMISE 전달력
- subject: 주요 피사체 크기·선명도
- legibility: 작게 봐도 보이는지, 문구가 있으면 읽히는지
- natural: 실사나 자연스러운 디자인처럼 보이는지. AI 티가 나지 않는지
- clean: 잡동사니, 시선 분산 요소가 없는지
- immediacy: 피드에서 한눈에 요점이 전달되는지
- textOk: 문구에 오탈자·깨짐이 있으면 false

## 11. 소제목 이미지

### 11.1 항상 참고하는 것

전체 제목 + CARD_PROMISE + 전체 소제목 + 현재 소제목 + 이전 이미지

### 11.2 소제목 역할 → 이미지 역할

소제목의 역할을 먼저 판단한다. 예: 실제 사건·장면 / 배경·회상 / 숫자·비교 / 선택 / 결과·주의. 이미지 역할도 서로 다르게 배정한다.

| 이미지 역할 | 신호 단어 예 | 구도 | 카메라 | 재생성 때 카메라 |
|---|---|---|---|---|
| 실제 장면 | 경위, 당시, 현장, 공개, 방송 | 그 순간과 실제 장소. 사람은 작게, 뒷모습·옆모습, 포즈 없음 | 눈높이 스냅, 주변 맥락, 있는 빛 | 낮은 어깨 너머 스냅 |
| 비교 | 차이, 비교, vs, 금액 두 개 | 비교 대상 둘을 같은 크기·같은 빛으로 좌우 배치. 사람 없음 | 정면 중간 거리, 고른 빛 | 위에서 본 나란히 배치 |
| 클로즈업 | 서류, 성분, 계약서, 영수증 | 결정적인 물건·문서 하나가 화면 대부분. 손은 가능, 얼굴 없음 | 매크로 디테일, 얕은 심도 | 3/4 각도 근접, 측광 |
| 행동·절차 | 방법, 신청, 절차, 순서 | 그 단계를 하는 손과 대상. 어깨 너머, 얼굴 없음 | 어깨 너머 중간 거리, 창가 빛 | 1인칭 내려다보기 |
| 선택 기준 | 기준, 조건, 자격, 체크리스트 | 골라야 할 항목을 실제 테이블 위에 간격 두고 배치. 사람 없음 | 탑다운 플랫레이 | 약 45도 테이블 뷰 |
| 장소 | 위치, 코스, 주차, 동선 | 그 장소를 넓게, 배치가 읽히게. 사람에 초점 없음 | 광각 설정 샷 | 눈높이 진입로 뷰 |
| 문제 상황 | 문제, 피해, 논란, 거절 | 문제 자체(손상, 반려 서류, 긴장된 현장). 얼굴은 프레임 밖 | 눈높이, 차분한 빛 | 낮은 근접 각도 |

신호 단어가 없는 소제목은 글 종류별 기본 순서에서 아직 안 쓴 역할을 받는다.

| 글 종류 | 기본 순서 |
|---|---|
| 이슈(연예·사건·법원·스포츠·방송) | 장면 → 장소 → 클로즈업 → 문제 → 기준 → 절차 |
| 정보(정책·금융·생활) | 장면 → 클로즈업 → 절차 → 기준 → 장소 |
| 제품 | 클로즈업 → 절차 → 기준 → 장소 → 장면 |
| 여행 | 장소 → 장면 → 클로즈업 → 절차 → 기준 |

비교는 기본값으로 쓰지 않는다. 비교할 두 대상이 없으면 의미 없는 분할 화면이 된다.

규칙:
- 이웃한 두 소제목은 같은 역할을 받지 않는다.
- 다섯 장 이하에서는 같은 역할을 반복하지 않는다.
- 배경만 바꾼 같은 이미지를 반복하지 않는다.
- 역할은 구도와 카메라만 정한다. 누가·무엇·어디는 소제목 내용에서만 온다. 역할이 사실을 만들어 내지 않는다.

### 11.3 실제와 AI 혼합

연예·이슈 글을 모두 AI 이미지로 채우지 않는다. 예시 흐름:

| 자리 | 이미지 |
|---|---|
| 썸네일 | 실제 박서함 + 실제 안소희 |
| 첫사랑 연예인 소제목 | 실제 인터뷰·인물 이미지 |
| 어머나와 양말 소제목 | AI 회상·팬굿즈·양말 이미지 가능 |
| 다른 대화 소제목 | 실제 출연자·방송 이미지 |

즉 REAL → AI → REAL → INFOGRAPHIC처럼 섞는다. 실제 이미지가 필요한 자리에 억지 AI 그림을 넣지 않는다.

## 12. AI 소제목 이미지 스타일

유지할 좋은 점:
- 소제목 의미가 즉시 보인다
- 감정선이 있되 과장되지 않는다
- 실제 생활 장면처럼 보인다
- 구도가 다양하다

줄일 것:
- 영화 포스터 같은 과한 조명
- 너무 완벽하게 배치된 소품
- 과한 감성 연출
- 같은 모델 반복
- 똑같은 정면·책상·스마트폰 장면
- 사람을 모든 컷에 넣는 습관
- AI가 만든 것처럼 지나치게 예쁜 장면

"예쁜 이미지"보다 "진짜 있을 법한 장면"을 우선한다. 앱은 역할이 배정된 실사 소제목 이미지의 브리프에 다음 두 문장을 붙인다. DeepInfra·Leonardo가 브리프를 짧은 영어 래퍼로 바꿔 쓰는 경우에는 빠진다.
- 실사 문장: 보정하지 않은 실제 사진처럼. 자연광, 실제 색, 약간 불완전한 구도, 생활감 있는 한국 공간. 스튜디오 광택, HDR, 네온, 과채도, 틸트시프트 없음.
- 클리셰 문장: 노트북·스마트폰·태블릿을 쓰는 사람이나 흰 배경 위 제품을 기본으로 쓰지 않는다. 그 기기나 제품이 소제목의 주제일 때만 쓴다.

## 13. 다양성 검사

새 소제목 이미지를 만들기 전에 직전 1~3장과 비교한다.
- 같은 사람? 같은 모델? 같은 옷?
- 또 스마트폰? 또 책상? 또 앉아 있음? 또 정면?
- 같은 촬영거리? 같은 배경? 같은 색감? 같은 이미지 유형?

겹치는 항목이 많으면 생성 전에 콘셉트를 바꾼다. 역할, 촬영거리, 장소 중 하나 이상을 바꾼다.

## 14. IMAGE QUALITY CHECK

이 검사는 새 LLM 호출을 기본으로 추가하지 않는다. 계획 단계의 메타데이터로 판단한다. 픽셀을 봐야 하는 항목(한글 깨짐, AI 느낌)은 고품질 모드의 심사가 맡는다.

썸네일 체크:
1. CARD_PROMISE와 같은가
2. 실제 핵심 엔티티가 맞는가
3. 실제 인물이 필요한데 가짜 AI 모델을 쓰지 않았는가
4. 모바일에서 대상이 식별되는가
5. 텍스트가 너무 긴가
6. 한글 오류가 있는가
7. 과도한 포스터·AI 느낌이 있는가
8. 실제 이미지를 쓸 수 있었는데 놓치지 않았는가

소제목 체크:
1. 소제목 의미와 직접 관련되는가
2. 이전 이미지와 너무 비슷하지 않은가
3. 사람이 불필요한데 사람을 넣지 않았는가
4. 지나치게 영화적이지 않은가
5. 실제 대상·장소를 잘못 재현하지 않았는가

FAIL 사유 예(앱의 결정적 검사가 내는 문구):
- "크기 1280x720 — NAVER 기본 800x800 아님"
- "제목 전체를 썸네일에 복사"
- "썸네일 문구가 너무 김"
- "실제 이미지가 있는데 AI부터 사용"
- "실존 인물 자리에 닮지 않은 AI 인물"
- "2·3번 소제목 이미지 역할이 같음(scene)"
- "다섯 장 이하인데 같은 역할이 반복됨"

검사 결과는 기록하고 알린다. 발행을 막지는 않는다. 최종 판단은 사용자가 한다.

## 15. 재생성

동일 프롬프트를 그대로 반복하지 않는다. 최소 하나 이상 바꾼다.
- 구도, 촬영거리, 시점, 피사체 크기
- 배경, 여백
- 그래픽 배치, 텍스트 위치
- 조명·연출

사용자 수정 요청이 있으면 그것이 최우선이다. 역할별 두 번째 카메라는 §11.2 표의 마지막 열이다.

## 16. 승인 흐름

상태 흐름:
```
생성 완료 → USER_DECISION_PENDING → (사용자 선택) → 다음 / 재생성 / 수정 후 재생성
```

생성 직후 묻는다.

썸네일:
> 썸네일 생성을 완료했습니다. 마음에 드시나요?
> 1. 다음 소제목 이미지
> 2. 바로 재생성
> 3. 수정사항 입력 후 재생성

소제목:
> 소제목 이미지 생성을 완료했습니다. 마음에 드시나요?
> 1. 다음
> 2. 다시
> 3. 수정 후 다시

- 사용자 선택 전에는 다음 이미지를 자동 생성하지 않는다.
- 이미지 도구의 제약으로 메뉴를 띄울 수 없어도 자동 승인하지 않는다. 다음 이미지로 넘어가지 않는다. 상태만 USER_DECISION_PENDING으로 유지한다.
- 예외: 사용자가 "전체 자동"을 명시적으로 켠 자동화(앱의 풀오토·연속 발행)는 그 설정이 승인이다.

## 17. 자동화 호환

외부 자동화가 값을 주면 다시 묻지 않는다.

| 필드 | 뜻 | 없을 때 |
|---|---|---|
| platform | NAVER / GOOGLE … | NAVER |
| title | 글 제목 | 필수 |
| headings | 전체 소제목 | 썸네일만이면 불필요 |
| currentHeading | 지금 만들 소제목 | 소제목 이미지 요청이면 한 줄 질문 |
| currentTask | thumbnail / section / set | 요청 문장에서 판단 |
| imageDirection | 사용자가 정한 방향 | 디렉터가 결정 |
| thumbnailTextMode | AUTO / 포함 / 미포함 | AUTO |
| references | 참조 이미지 | 없음 |
| sourceUrl | 기사·출처 URL | 없음(URL은 REFERENCE_ONLY) |
| sourceImages | 실제 이미지 | 없음 |
| previousImages | 이전 이미지 정보 | 없음 |
| size | 크기 | NAVER면 800x800 |
| CARD_PROMISE | 클릭 이유 한 문장 | 디렉터가 제목으로 만든다 |

모든 값이 들어오면 질문 0회로 바로 진행한다.

## 18. 상태 관리

같은 글에서 유지한다: articleId, title, headings, CARD_PROMISE, PrimaryIntent, currentImageIndex, imageDirection, thumbnailTextMode, asset inventory, references, previousImages, 사용한 모델·피사체·구도, 사용자 수정사항, approval state.

새 글이면 전부 초기화한다. 제목이 바뀌거나 articleId가 바뀌면 새 글이다.

## 19. 분야별 규칙

### 19.1 정보 · 정책 · 금융

실제 인물이 필요 없는 글은 억지 실사 인물 대신 정보 전달형 이미지를 쓴다.
- 지원금: 신청 화면, 조건, 기간, 금액 비교
- 세금: "18억 vs 12억" 비교, 신청 기간, 선택 구조
- 보험: 상황, 절차, 비교
- 동전 더미, 돈다발, 돼지저금통, 판사봉, 돈 위 계산기 같은 클리셰는 쓰지 않는다

### 19.2 자동차 · 제품

실차·실제 제품 이미지를 우선한다. 가격·주행거리는 시각화한다. 실제 디자인, 색, 비율을 바꾸지 않는다. 없는 변형 모델을 만들지 않는다.

### 19.3 여행 · 축제

실제 장소 사진을 우선한다. 존재하지 않는 건물, 꽃밭, 시설을 만들지 않는다. 정보가 핵심이면 주차, 셔틀, 동선, 예약을 시각화한다. 관광 광고 포스터 느낌은 금지다.

### 19.4 연예 · 이슈

§6을 따른다. 실제 인물 사진이 없으면 인물 없는 상징형으로 간다. 소제목 이미지에서도 실존 인물이나 닮은꼴을 그리지 않는다. 장소, 사물, 문서, 상징적 디테일을 보여주고, 사람은 작게, 뒷모습으로, 식별할 수 없게 둔다.

| REAL 우선 주제인데 실제 자료가 없음 | 정직한 상징형 AI(§6.3) + 업로드 안내 한 줄 |
| 기사 URL만 있음 | REFERENCE_ONLY. 원본을 받아 합성하지 않는다. 외형 참고만 한다 |
| 권리 불확실 | REFERENCE_ONLY. 게시용 자산으로 쓰지 않는다 |
| 한글 깨짐·숫자 오류 | 미완성. 문구 없는 이미지 + 앱 합성 문구로 다시 만든다 |
| 사용자가 크기 지정 | 그 크기. 세트 전체에 같은 크기 |
| GOOGLE 등 다른 플랫폼 | 그 플랫폼의 기존 설정 |
| 쇼핑커넥트 | 수집한 실제 제품 이미지가 썸네일. 제품 정체성 유지 |
| 소제목이 없음 | 썸네일만 가능. 소제목 이미지는 한 줄 질문 |
| 이미지 엔진이 글자를 직접 그림 | 짧은 문구만 정확히 지정한다. 제목 전체는 주제로만 준다 |
| 비용 한도 | 기본 1장. 고품질 후보는 사용자가 켰을 때만 |

## 22. 회귀 fixture: 박서함 / 안소희

제목: "소희 양말 신던 중학생이었다…박서함 팬심 고백에 담긴 기억"

### BEFORE (실패한 썸네일)

| 특징 | 위반 규칙 |
|---|---|
| 실제 박서함 대신 임의 AI 남성 | §6.2 관계없는 AI 모델 |
| 실제 안소희 대신 화보 같은 가짜 이미지 | §6.2, 닮은꼴 금지 |
| 테이블·옷·양말을 한 장에 억지 배치 | §8.2 소품 과다, 주요 대상 1~2개 |
| 제목 전체를 긴 텍스트로 삽입 | §9 제목 전체 복사 |
| 연예 이슈인데 AI 상황극처럼 보임 | §6.2 재연 금지 |

→ 판정: **FAIL**. GOOD으로 판정되면 안 된다.

### AFTER (기대 방향)

1. 실제 박서함 이미지를 쓸 수 있는지 먼저 확인한다.
2. 실제 안소희 이미지를 쓸 수 있는지 먼저 확인한다.
3. 실제 자료가 있으면 합성·편집형 썸네일을 만든다.
4. 실제 자료가 없으면 정직한 상징형으로 간다. 인물 없이 양말, 옛 음반, 팬굿즈 같은 사물을 쓴다. 닮은꼴은 만들지 않는다.
5. 양말은 보조 포인트다.
6. 텍스트는 짧게: "중학생 때 / 소희 양말" 또는 "소희 양말도 신었어요".
7. 크기는 800x800.

### 소제목 GOOD 사례 두 장

| 소제목 | 좋은 점 | 줄일 점 |
|---|---|---|
| 첫사랑 연예인으로 꼽은 안소희 | 회상·팬심 의미가 잘 전달됨 | 영화 포스터 느낌, 과한 조명 |
| '어머나'와 소희 양말의 연결 | 학창시절·양말·팬심이 바로 보임 | 너무 완벽한 연출, AI 티 |

개선 방향: 의미는 그대로 둔다. 조명, 연출, 광택을 한 단계 낮춘다. 두 이미지는 서로 다른 역할(예: 장면과 클로즈업)을 받는다. 실존 인물이나 닮은꼴은 그리지 않는다.

## 24. 완전자동 이미지 전략 (SPEC-NAVER-FULLAUTO-2026, 2026-09-24)

글쓰기 모드와 이미지 전략은 따로 정한다. SEO로 쓴 글도 이미지는 홈판용이다.

| 항목 | 홈판/피드 최적화 (기본) | 내 이미지 설정 그대로 |
|---|---|---|
| 크기 | 1:1 요청 + 800x800 강제(비율을 무시하는 엔진 포함) | 설정한 비율 |
| 썸네일 | 항상 1장 (서론이 없어도) | 항상 1장 |
| 소제목 | 최종 H2당 1장, 범위 전체/홀수/짝수/없음(1-based) | 같음 |
| 썸네일 문구 | AUTO(숫자·기간·비교일 때만 짧게) / 넣기 / 빼기 | 썸네일 텍스트 체크박스 |
| 실제 사진 | 우선 사용, 2장이면 나란히 합성 | 같음 |

- 예약 큐 항목은 넣는 순간 이미지 전략·소제목 범위·문구를 고정한다(새 항목 기본: 전체).
- 슬롯: 썸네일 + h2-1…h2-N. 실패한 칸은 비워 두고 뒤 이미지가 밀리지 않는다.
- 발행 판단: 필수 이미지(썸네일 + 범위 안 H2)가 모두 있고, 선택 엔진으로 만들어졌고, 이미지 뒤에 소제목이 바뀌지 않았을 때만 자동 발행. 아니면 "이미지 검토 필요" — 글과 성공 이미지는 저장, 발행 안 함.
- 자동차 글: 증상/문제 → 문제 부위, 실구매가·보조금·트림 → 비교, 옵션·기능·계기판·충전구 → 클로즈업. 도로 위 자동차 같은 일반 컷 금지.
- 정책·금융·보험·IT: 동전 더미·돈다발·판사봉·우산 가족·네온 회로 금지.
