# Vultr 공백 메우기 설계

Vultr($52/월)를 폐지하면서 그 위에 있던 기능들이 갈 곳을 잃었다. 이 문서는
**Vultr가 하던 일을 하나씩 어디로 넘길지** 정한다.

전제: 새 서버를 사지 않는다. 이미 가진 것(GitHub Pages·GitHub Releases·GAS·
사장님 PC)만으로 메운다.

---

## 0. 지금 실제로 깨져 있는 것 (2026-08-08 실측)

| 증상 | 원인 |
|---|---|
| 🔴 구매자 다운로드 실패 | GAS site-content 의 `downloads.naver.windows.url` 이 **빈 문자열**. Vultr 에 파일을 올려 URL 을 채우던 방식이었는데 서버가 없어지며 빈 값만 남음 |
| 🔴 관리자 로그인 불가 | 클라이언트 해시가 빈 문자열(`sha256(x) === ''` 은 항상 거짓) + 서버 인증이 폐지된 `/v1/web/session` 을 호출 |
| 🟡 어드민 화면 404 다발 | API base 만 자리표시자로 바꾸고 호출은 안 막음 (수정 완료, 미배포) |
| 🟡 황금보드 정지 | 24h 워커가 Vultr 에 있었음. 정적 스냅샷 발행 경로(M0 브리지)는 만들어졌으나 한 번도 발행 안 됨 |

파일 자체는 멀쩡하다 — GitHub Releases 10개 전부 HTTP 200, 용량 정상.
**끊긴 건 파일이 아니라 "어느 파일을 받아야 하는지 알려주는 경로"다.**

---

## 1. 책임 재배치

Vultr 가 지던 5가지를 네 곳으로 나눈다.

| Vultr 가 하던 일 | 옮길 곳 | 이유 |
|---|---|---|
| 설치 파일 호스팅 | **GitHub Releases** | 이미 실제 파일이 거기 있다. 용량 무제한·CDN·무료. Vultr 는 애초에 중복이었다 |
| 버전·URL 등록 | **GAS site-content** | 이미 `downloads` 스키마가 있다. 값만 비어 있을 뿐 구조는 그대로 쓸 수 있다 |
| 공개 데이터 서빙 | **GitHub Pages 정적 스냅샷** | source-signals 는 이미 이 방식으로 돌고 있다(15분 크론) |
| 황금보드 생성 | **사장님 PC 배치** | BD + 로컬 LLM 파이프라인이 오늘 만들어졌다. 결과를 스냅샷으로 커밋 |
| 관리자 인증 | **GAS** | 라이선스·주문을 이미 GAS 가 인증하며 다룬다. 인증 주체가 둘일 이유가 없다 |

핵심 원칙 하나: **파일을 옮기지 말고 주소만 관리한다.**
Vultr 시절엔 어드민이 파일을 청크로 업로드했다(`/v1/admin/downloads/upload-chunk`).
그럴 필요가 없다. 릴리스는 이미 GitHub 에 올라가므로, 어드민은 "어느 릴리스가
최신인지"만 기록하면 된다. 업로드 기능은 되살리지 않고 버린다.

## 2. 다운로드 복구 — 가장 급한 것

### 지금 구조
```
DownloadPage ──(기본값: GitHub Releases URL 하드코딩)
            └──(GAS site-content.downloads 로 덮어쓰기)  ← 여기가 빈 값
```
코드는 빈 URL 이면 기본값으로 되돌리게 되어 있다(`configured.url?.trim() || item.url`).
그런데 라이브 화면엔 링크가 하나도 안 걸려 있다. **이 불일치가 아직 안 풀렸다.**

### 확인해야 할 것 (다음 세션 1순위)
버튼이 `<a href>` 가 아니라 클릭 핸들러/비밀번호 확인 후 이동 방식일 가능성이 크다.
구매자가 정확히 어디서 막혔는지(버튼 무반응 / 비밀번호 단계 / 링크는 떴는데 404)를
알면 바로 좁혀진다.

### 복구 설계
1. **단일 진실 = GitHub Releases.** GAS 값이 비었거나 낡으면 **무시**하고 코드 기본값을 쓴다.
   지금 코드는 "빈 값" 만 무시한다. **낡은 버전도 무시**하도록 넓힌다 —
   GAS 가 2.11.66 인데 코드가 2.11.182 면 코드가 이긴다.
2. **버전 표시와 링크가 어긋나지 않게 한다.** 현재 화면은 GAS 버전(2.11.66)을 보여주며
   실제로는 2.11.182 를 받게 되어 있다. 사용자가 뭘 받는지 모른다.
   버전·용량·링크는 **한 출처에서 같이** 온다.
3. **다운로드 헬스체크.** 릴리스 URL 이 실제로 200 인지 주기적으로 확인하고,
   깨지면 배포를 막는다. 오늘처럼 조용히 죽는 걸 다시 겪지 않는다.

## 3. 관리자 인증

### 현실
- 클라이언트 해시 검사는 **개발자도구로 우회된다**(`sessionStorage.admin_auth='1'`).
  즉 지금도, 해시를 되살려도, 보안 장치가 아니다.
- 진짜 방어는 GAS 가 해야 한다. GAS 는 이미 라이선스·주문·코드풀을 다룬다.

### 단계
1. **즉시(오늘)** — `scripts/set-admin-login.mjs` 로 클라이언트 해시 복구.
   사장님 접근을 되살리는 용도. 보안 향상은 아니며 그렇게 표시한다.
2. **다음** — GAS 에 `admin-login` 액션 추가. 아이디/비밀번호를 스크립트 속성에 두고
   짧은 수명 세션 토큰을 발급. 어드민은 그 토큰으로만 쓰기 작업을 한다.
3. **그 다음** — 쓰기 액션(`site-content` 저장, 공지 등록)에 토큰 검증 의무화.
   토큰 없으면 거부. 이게 실제 방어선이다.

⚠️ GAS 콘솔 작업은 사장님만 가능하다. 2·3단계는 사장님 손이 필요하다.

## 4. 황금보드

워커가 없어졌으므로 **사장님 PC 배치**가 대신한다.

```
run-core-golden-ingest (후보 발굴)
      ↓
brightdata-board-batch (SERP 판정, 최종 96 + 탈락 표본)
      ↓
publish-golden-snapshot (정적 JSON 발행)
      ↓
GitHub Pages 커밋 → SPA 가 읽음
```

3단계는 이미 다 만들어져 있다. 남은 건 **연결과 스케줄링**이다.
PC 가 꺼져 있으면 갱신이 멈추지만, 정적 스냅샷이 남아 있어 화면이 깜깜해지진 않는다.
(이 폴백은 오늘 홈페이지 장애 때 실제로 작동했다.)
