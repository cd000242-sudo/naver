## 핵심 구현 1: 블로그마다 다른 초기 설정

라이선스 사용자와 실제 NAVER 블로그 ID를 분리한 안정적인 식별자로 저장한다. 같은 라이선스로 A/B 블로그를 운영해도 설정, 사례, 성과, 캐시가 섞이면 안 된다.

초기 설정 흐름:
1. 연결된 블로그 선택 및 실제 주소/ID 확인.
2. 주제/카테고리, 주 독자, 독자 상황/질문, 운영 목적, 검색형/홈판형/혼합 방향을 입력한다. 방향은 사용자가 편집할 수 있다.
3. 최근 공개 글과 실제 성과 자료를 분석한다. 계정 권한이 없으면 CSV/JSON 가져오기 또는 수동 입력을 제공하고 분석 가능한 범위를 명시한다.
4. 잘된 글뿐 아니라 약한 글도 수집한다. 추천 독자 설정/문체/소재 축과 근거를 보여주고 사용자가 확인해 저장한다.
5. 이후 설정 화면에서 수정/재분석/내보내기/삭제할 수 있다. 버전과 갱신일을 남긴다.

저장할 개념: reader profile, subject scope/exclusions, search/homefeed intent, reader questions, voice examples/preferences, primary sources, benchmark cases, observed performance references, source provenance, profile version. 기존 타입/저장소에 맞추고 비슷한 추상화를 중복 생성하지 않는다.
신규 블로그는 통계가 없어도 최소 독자/주제 설정 후 시작할 수 있어야 한다. 관측이 없는 부분은 가설/초기 설정으로 표시하고 가짜 성과를 채우지 않는다.
운영자 3계정은 테스트 예시이지 모든 고객에게 고정하는 목록이 아니다. 공개 앱은 고객이 연결한 각 블로그를 사용한다. 실제 운영 도구는 허브의 허용 3계정만 접근하며 경제/애드센스는 제외한다.
기존 고객은 opt-in/확인 가능한 비파괴 마이그레이션을 제공한다. 기존 원고, 예약, 계정 연결, 이미지/엔진/예약 시각 설정을 자동 변경하지 않는다.

## 핵심 구현 2: 규칙 추가가 아닌 생성 파이프라인

목표 흐름:

- 키워드만 넣고 바로 제목을 뽑는 경로를 새 엔진의 정상 경로로 남기지 않는다. URL 원문 기반도 동일한 독자 질문/근거 단계를 거친다.
- Situation/Problem/Desire/Fear/Loss/Conflict/Curiosity/Timing/Identity/Social Tension을 구조화한다. 근거 없는 감정/공포를 만들지 않고 해당 없는 축은 null로 둔다. 사용자에게 긴 심리 설문 10개를 강요하지 않는다.
- 출처는 발행일/사건일/시장/모델/예고 대 실제 방송 등 조건을 보존한다. 공급자 보도자료를 구하기 쉽다는 이유만으로 주제를 선택하지 않는다.
- 제목이 약속한 주장/답과 이를 뒷받침하는 원문 위치, 실제 이미지 장면을 연결한다. 중요한 답이 없으면 더 조사하거나 범위를 좁히고, 그래도 없으면 보류한다.
- 사례 검색은 이름/키워드만 비슷한 글이 아니라 독자 심리, 증거 형식, 클릭 동기, 질문/답 구조가 유사한 사례를 찾는다. 사례의 고유 표현/본문을 베끼지 않는다.
- 성공 사례의 출처/기간/지표가 없으면 참고 패턴일 뿐 검증된 성공으로 분류하지 않는다. 저성과 대조군도 유지한다. 원본 1,760행이 확보되지 않으면 그 부분은 미확보로 표시하고 진짜로 확보한 사례만 쓴다.
- 50~100개는 매번 전체 본문을 100번 쓰라는 뜻이 아니다. 서로 다른 진입 방식의 짧은 후보를 배치 생성/중복 제거하고 최종 후보만 상세 검수한다. 비슷한 단어 바꿈 100개는 실패다.
- 인물/제품명만 바꿔도 성립하는 범용 제목, 내용 없는 왜/알고 보니/먼저 확인, 억지 결말 은폐는 탈락시킨다. 형태 일괄 금지로 우회하지 않는다.
- AI 토너먼트 점수는 편집 판단이다. 성공 확률/실제 클릭률로 표시하지 않는다. 점수만으로 증거 없는 후보를 통과시키지 않는다.
- 초반에 제목의 핵심 답을 제시하고 이후엔 다른 근거/장면/판단 정보를 준다. 추상적 감상, 근거 없는 일인칭 경험, 반복으로 분량을 채우지 않는다.
- 말투는 블로그별 실제 예문을 바탕으로 조절하되 사실/숫자/직접 인용은 Humanizer가 바꾸지 못하게 한다.

- 다음 소재 선정과 사례 검색에서 실제 해당 블로그 성과를 읽도록 연결한다. CSV를 저장만 하거나 화면만 만드는 것으로 끝내지 않는다.

- 통계/비공개 원문을 외부 AI에 전송한다면 범위, 동의, 민감값 제거, 계정 격리, 삭제까지 기존 개인정보 정책과 맞춘다. 프로필 변경/통계 갱신/생성 시작 간 경합도 방지한다.

## 운영 안전 경계

이번 요청은 앱 개발이다. 기존 공개/예약/임시저장 글을 수정하거나 새 글을 실제 공개하는 권한으로 확대하지 않는다.
허브 active_engine을 앱 개발만으로 claude로 전환하지 않는다. 실제 블로그 운영을 인수할 때만 active_job과 최신 허브 지침을 확인한다.
기존 계정별 일20편, 공개 시각, 60분 전 준비, 이미지 방식 등 사용자 설정은 성과 개선을 이유로 변경하지 않는다. 품질 기준을 충족 못하면 글 수를 채우기 위해 날조하지 말고 미달/보류를 표시한다.
앱은 현재 반자동 전달/검토 경로이며 실제 NAVER 예약 목록 어댑터 미연결 경로는 보류한다. 설정 저장이나 테스트 통과를 자동 예약 완료로 설명하지 않는다.
트래픽 구매/가짜 방문/불법 수집/댓글 스팸/허위 논란/저작권 무시/순위 보장은 해결책이 아니다.
설치 앱 교체, 실행 중 앱 강제 종료, 공개 다운로드 업로드, Web Store 제출은 별도 요청 없이 하지 않는다.

## 구현 순서와 완료 기준

1. 현재 코드/dirty 작업/실제 진입점을 조사하고 변경 범위와 데이터 계약을 짧게 기록한다. 기존 daily 편집 기능이 있으므로 처음부터 중복 제작하지 않는다.
2. 블로그별 프로필 저장/비파괴 마이그레이션/초기 설정 UI를 TDD로 구현한다.
3. 사례/성과 저장과 가져오기, 독자 질문/근거/후보/검수 단계를 실제 수동 작성 및 daily 생성 진입점에 연결한다. 선택한 블로그와 프로필 버전을 작업 시작에 고정한다.
4. 발행 상태 대조와 경과 시간별 측정/환류를 구현한다. 실제 수집 어댑터와 개발 fixture를 명확히 분리한다.
5. 기존 품질/취소/엔진/이미지/예약 안전 회귀를 돌리고 npm run build를 확인한다. 현재 package.json 명령을 재확인한다. live publish/login 테스트는 무심코 실행하지 않는다.
6. 분리된 테스트 사용자 데이터로 실제 Electron 화면을 검증한다: 신규 설정 -> 저장 -> 재시작 -> 블로그 변경 -> 분석 -> 생성 -> 근거/결과 확인 -> 성과 가져오기 -> 다음 생성 입력 반영. 앱을 건드릴 필요가 있으면 사용자의 실행 중 원고부터 보존한다.
7. 변경 파일/테스트/실화면 증빙/실제로 안 된 부분을 보고한다. 배포 안 했다면 그렇게 적는다. 계획만 전달하고 완료 처리하지 않는다.

필수 실패/회귀 테스트:
- 같은 라이선스의 서로 다른 블로그에서 프로필/성과/캐시가 섞이지 않음. 전환 중 실행 작업도 잘못된 계정에 저장되지 않음.
- 통계 없는 새 블로그 시작 가능, 누락 지표와 실제 0의 구분, 잘못된/타 블로그 통계 가져오기 차단.
- 동일한 키워드라도 서로 다른 독자 설정이 실제 생성 payload/사례 검색/소재 선택에 반영됨. 설정 문자열 존재 검사만으로 통과시키지 않음.
- 제목의 이유/답 근거가 없는 예고편은 보류, 단어만 바꾼 후보는 중복 처리, 원문 뒤쪽에 있는 결정적 답도 누락 없이 조사.
- 제목 고정/제목 변경 없음/제목 재생성 모든 분기의 최종 사실/약속 검수 실패 시 전달/발행이 막힘.
- 사례/원문/CSV의 프롬프트 인젝션, 부적절한 경로/URL, 큰 입력에 대한 검증.
- 중지/timeout 후 늦게 도착한 결과가 작업을 되살리지 않음. 재개/재시도 시 유료 중복 호출과 중복 원고 방지.
- 기존 원고/예약/라이선스/엔진/이미지 모드가 그대로 보존됨. 외부 AI 실패가 다른 벤더/구형 생성기로 자동 변경되지 않음.

## 이번 인계 준비에서 실제 한 일

Codex는 진단 자료와 앱의 주요 편집/계정 설정 소스, package.json, dirty 상태, 로컬 claude --help를 확인했다.
이 인계 문서만 새로 만들었다. 앱 생성 엔진/초기 설정을 구현하거나 앱 빌드/배포/실계정 생성 테스트를 실행하지 않았다.
클로드 실행 명령은 사용자가 시작한다. 새 Claude 세션에 이 대화 전체가 자동 이전된다고 가정하지 않는다.
