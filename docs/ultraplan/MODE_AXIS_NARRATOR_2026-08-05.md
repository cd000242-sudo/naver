# 모드별 카테고리 프롬프트 설계 규격

**결론 먼저.** 지금 카테고리 프롬프트를 아무리 잘 고쳐도 글은 안 바뀝니다. **글을 다 쓴 다음에 코드가 "실제로 사용해보니", "사용한 지 3개월째인데" 같은 가짜 경험 문장을 본문에 직접 끼워 넣기 때문**입니다(실측 근거 아래). 그래서 이 규격의 1번 릴리즈는 프롬프트가 아니라 **그 삽입기 차단**이고, 프롬프트 스키마는 그 다음입니다.

비유하자면 — 지금 상태는 주방에서 레시피를 아무리 다듬어도, 서빙 직전에 홀 직원이 접시마다 케첩을 뿌리고 나가는 겁니다. 레시피 회의(프롬프트)를 먼저 하면 안 되고, 케첩 통을 먼저 치워야 합니다.

### 0-1. 최대 발견 — 후처리가 매 글에 가짜 경험을 넣는다 (실측)

```
src/contentOptimizer.ts:329   if (!skipDictInjection) { result = enhanceEEAT(result, toneStyle, silent); }
src/contentOptimizer.ts:562   const targetCount = Math.max(2, Math.floor(paragraphs.length * 0.18));
src/contentOptimizer.ts:574   const category = categories[enhanced % categories.length];   // categories[0] === 'experience'
src/contentOptimizer.ts:182-188  professional.experience:
      '실제로 사용해보니', '직접 경험한 바로는', '현장에서 느껴본 결론은',
      '오랫동안 지켜본 결과', '수많은 사례를 검토해보니'
```

`enhanced % 4`이므로 **첫 번째 삽입은 항상 `experience`입니다.** 즉 문단 2개 이상인 모든 글에 가짜 경험 문구가 최소 1개 확정 삽입됩니다.

그 다음 단계가 하나 더 있습니다.

```

src/authgrDefense.ts:406         insertExperienceExpressions(citationResult.content, 2);
src/authgrDefense.ts:411         injectExtendedExperience(experienceResult.content, category, 1);

src/authgrDefense.ts:352         const periods = ['2주','한 달','3개월','6개월','1년'];   // Math.random()
```

`insertExperienceExpressions(content, 2)`의 시그니처에 **자료(source) 인자가 없습니다.** 근거가 있든 없든 무조건 2개를 넣고, 사용 기간은 **난수**입니다.

**꺼지는 조건이 사실상 없습니다.** `skipDictInjection = isLlmRubricEnabled(...) || source.skipDictInjection === true`(`contentGenerator.ts:6666-6668`)인데, `isLlmRubricEnabled`는 `process.env.USE_LLM_RUBRIC === 'true'`(`contentSemanticScoring.ts:157`)이고 이 환경변수를 세팅하는 코드가 없습니다. `skipDictInjection`을 true로 넘기는 렌더러/IPC 코드도 없습니다.

그리고 결정적으로 — **이 문구들은 근거 게이트에 걸리지 않습니다.** `evidenceIntegrity.ts:30-33`의 3개 패턴 어디에도 `실제로 해보니까`, `직접 비교해본 결과`, `제 경우에는`이 매칭되지 않습니다.

> **판정:** "경험 날조 금지"는 지금 프롬프트에만 있는 계약이고, 런타임은 정반대로 동작합니다. 이 배선을 끊기 전에 하는 모든 프롬프트 작업은 측정조차 불가능합니다.

**부수 발견 (같은 계열).**
- `src/contentHumanizationPolicy.ts:11` — `resolveHumanizeIntensity(_mode?)` 가 인자를 무시하고 항상 `'strong'` 반환. 그런데 호출부 주석(`contentGenerator.ts:6578`)은 여전히 `"SEO/Homefeed/Mate는 개인 표현·감탄사·동의어를 새로 삽입하지 않는다"`. **주석이 코드보다 오래됐습니다.**

- `src/prompts/shared/strong-headings.prompt`(105줄, `SH-7 1인칭 경험 흔적 5개 중 2개 의무`)는 **로드되지 않습니다.** `loadPromptFile` 호출 0건, 참조는 `candidateRuntimeFingerprint.ts:452`(지문 목록)뿐. 살아있는 룰로 취급하면 안 됩니다.

## 2. 화자 설계 — 1인칭을 어디까지 여는가

**결론:** 5종(판단·조사·정리·권유·전달)을 열고 체험만 닫습니다. 다만 **"의미"가 아니라 "표기(어형)" 단위로** 엽니다. 근거 검출기가 같은 행위를 어미로만 갈라서 한쪽은 하드 실패를 주기 때문입니다.

### 2-1. 허용 유형 표

|---|---|---|---|---|
| **판단** | 예 (자료 보고 판단함) | **허용** | "~라고 봐요", "제 기준으로는", "여기가 갈림길이에요" | — |

### 2-2. "제가 보기엔"이 "제가 써보니"로 미끄러지지 않게 하는 장치 — 5중

미끄럼은 **가능성이 아니라 현재 기본 동작**입니다(§0-1). 그래서 장치는 프롬프트 1개가 아니라 5개여야 합니다.

**장치 1 (가장 중요) — 후처리 삽입기 차단.**
`contentOptimizer.ts:329`(enhanceEEAT), `:350`(applyAuthGRDefense) 두 곳. 이걸 안 끊으면 나머지 4개는 전부 무의미합니다. **R1 릴리즈.**

**장치 2 — 어형 지정 (검출기 우회).**
`evidenceIntegrity.ts:31` 정규식은 `(제가|저는|…)[^.!?\n]{0,35}(직접|…해\s*봤|비교해\s*봤|…)`입니다. 즉 **"제가 자료를 직접 찾아보니"는 하드 실패**입니다(`직접` 단독 매칭). hard fail은 `safetyEval.ts:153` `finalScore = Math.min(finalScore, 35)` → `qualityEvaluator.ts:87` `safety < 50 → 'regenerate'` → **유료 재생성 1회**. 그래서 지시문 예시에 `직접`과 `~해 봤`을 **절대 넣지 않습니다.**

**장치 3 — 대상 목록 명시.** "열린 것"과 "닫힌 것"을 같은 블록에서 나란히 씁니다. 금지만 있으면 모델은 1인칭 전체를 회피하고, 허용만 있으면 체험까지 번집니다.

**장치 4 — 빈도 상한.** 글 전체 2~4곳. `aiHumanizer.ts:338`의 8% 랜덤 삽입과 겹쳐 후렴이 되는 걸 막습니다.

**장치 5 — 순서 계약.** "판단은 근거 뒤에 온다." 자료에 없는 사실을 "제가 보기엔"으로 감싸 통과시키는 환각 세탁 통로를 막습니다.

## 3. 26파일 공통 스키마

**결론: 5슬롯. 그리고 파일 구조를 26 → 13+13+13으로 바꿉니다.**

### 3-1. 왜 파일 구조를 바꾸는가

지금 SEO판·홈판판이 겹치는 41%(재측정 38%)의 정체를 열어보면 **26쌍 중 13쌍이 "1인칭 게이트" 한 문장**입니다.

```
society 자카드 1.00
   SEO: 사용자 직접 신청·금융 메모가 있을 때만 과정과 결과를 1인칭으로 쓴다.
   홈판: 사용자 직접 신청·금융 메모가 있을 때만 과정과 결과를 1인칭으로 쓴다.
```

두 벌은 런타임에 함께 들어가지 않으므로(`promptLoader.ts:202`가 모드별로 하나만 로드) **토큰 낭비도 충돌도 아닙니다. 드리프트 위험이고, 이미 벌어졌습니다** — `seo/health.prompt`는 11불릿 신규격인데 `homefeed/health.prompt`는 6불릿 구규격입니다(§0 정정 3). `seo/it.prompt:3`은 "출시 시점"이 있는데 `homefeed/it.prompt:4`는 없습니다.

**같은 규칙을 두 곳에 적어두면 언젠가 한쪽만 고칩니다. 그러니 한 벌로 만듭니다.**

```
src/prompts/
  category/{cat}.prompt    ← 신설 13개. 모드 불변 규율 (S2·S3·S5)
  seo/{cat}.prompt         ← 기존. S1(검색 판정축) + S4(SEO 배치)만
  homefeed/{cat}.prompt    ← 기존. S1(피드 멈춤축) + S4(홈판 배치)만
```

로더 변경은 `promptLoader.ts:202` 뒤 3줄:

```ts
// 2.4 Category-invariant regulation (evidence binding / harm / forbidden phrasing).
// Mode files carry only the judgment axis and first-screen placement.
// Silently skipped when absent — keeps half-migrated states safe.
const invariant = loadPromptFileOptional(`category/${category}.prompt`);
if (invariant) composed = `${composed}\n\n${invariant}`;
```

`loadPromptFileOptional`이 필요한 이유: 현행 `loadPromptFile`(`:148`)은 실패 시 `console.warn`을 찍습니다. 마이그레이션 중 미이전 카테고리에서 매 생성마다 경고가 나면 로그가 죽습니다.

### 3-2. 슬롯 목록

**공리:** 카테고리 파일은 **base가 이미 허용한 것을 좁히는 문장만** 씁니다.

판정식(사람·기계 공용): *그 불릿에서 카테고리 고유명사(장소·증상·사료·정책·모델명)를 지운다. 남은 문장이 다른 12개 파일에서도 참이면 → base 소관 → 삭제.*

| # | 슬롯 | 답해야 할 질문 | 모드 | 상한 |
|---|---|---|---|---|
| **S1** | 판정축 | 이 카테고리 독자가 실제로 내리는 결정 하나는 무엇이고, 그 결정을 가르는 조건은 무엇인가 | **모드 분기** | 2~4불릿 |
| **S2** | 근거 결속 | **무엇이 입력에 있어야** 무엇을 쓸 수 있는가 (항목명 목록) | 불변 | 2~4불릿 |
| **S3** | 고유 위험 | 이 카테고리에서만 생기고 base가 못 잡는 피해는 무엇인가 | 불변 | 0~4불릿 (**비어도 정상**) |
| **S4** | 배치 | 첫 화면에 무엇을 두는가 | **모드 분기** | 정확히 1불릿 |
| **S5** | 고유 금지 | 이 카테고리 특유의 수사·클리셰 | 불변 | 0~2불릿 |

**밀도 예산:** 모드 파일 6불릿/500자, 불변 파일 8불릿/800자.
근거: 중복 0%를 실측 달성한 유일한 두 파일이 `seo/health.prompt`(11불릿/1,127자)·`seo/pet.prompt`입니다. 이 크기가 품질을 올린다는 증거는 없고, **중복 0을 달성한 파일의 실제 치수**라는 사실만 있습니다. 구규격 6불릿/300자 대비 약 3.5배 증량 여지이므로 "하네스 밀도"는 상한이 아니라 하한 쪽 문제입니다.

### 3-4. SEO판 ↔ 홈판판 경계선

**갈리는 것은 S1과 S4뿐입니다.** "종이 명시 안 되면 급여량 쓰지 마라"는 SEO에서도 홈판에서도 같습니다.

## 4. 우선순위 표기 규격

**결론: ★ 3줄 헤더 고정.** 기존 표기 중 유일하게 완전한 것은 `homefeed/issue-story.prompt:5-6`(이기는 대상·지는 대상 둘 다 명시)이므로 이걸 표준으로 승격합니다. `seo/health.prompt:3`의 `★ base.prompt [SECTION -2]…가 이 파일보다 항상 우선한다`도 같은 계열이라 파일명만 보강하면 그대로 맞습니다.

```
★ [ID] {파일 역할 한 줄}
★ 우선: {구체 룰 ID 목록}보다 우선한다.        ← 없으면 "우선: 없음"
★ 양보: {구체 룰 ID 목록}은 언제나 이 파일보다 우선한다.   ← 최소 1개 필수
```

### 판정 규칙

1. **참조는 반드시 `파일 + 룰 ID` 쌍.** `base H5`(✗) → `seo/base.prompt H5`(○). 같은 ID가 seo/homefeed에 각각 있을 수 있어 파일 없는 참조는 무효.
2. **범위 표기 금지.** `geo-overlay.prompt:6`의 `R0-1~R0-11`은 base가 R0-14까지 늘어나 이미 stale입니다. `situation-depth.prompt:5`의 `homefeed GAMMA-7·R0-14`에서 R0-14는 `homefeed/base.prompt`에 **존재하지 않습니다**(R0- 출현 0회). 열거하거나 `seo/base.prompt [SECTION 0] 전체`처럼 섹션 단위로 씁니다.
3. **"양보" 최소 1개 강제.** 무엇에도 지지 않는 파일은 존재해선 안 됩니다. 최소한 근거 게이트(`[SECTION -2]`)에는 집니다.
4. **부호 의미 고정.** `★`=우선순위·적용조건 선언 / `⛔`=상위 룰을 끄는 지점 / `-`=일반 규율. 기타 이모지 금지(현행 `🔥`·`🪤`는 `title/` 계열 유산).
5. **비활성 선언 고정 문형:** `⛔ {파일} {ID}는 이 파일에서 비활성이다.` 선례: `seo/health.prompt:10` `⛔ base [SECTION -0.5] AdPost 컨텍스트 매칭은 이 카테고리에서 비활성이다.`
6. **암묵적 덮어쓰기 금지.** 후행 우선이 기본이지만, 앞선 룰을 뒤집으려면 ★ 또는 ⛔로 명시해야 합니다.

### 선행 조건 — F 네임스페이스 충돌 (R3에서 처리)

`seo/base.prompt` 한 파일에 F1이 둘입니다.
- `:11` `F1. **자료 외 사실 작성 금지**`
- `:471` `F1. 1문장 단락 최소 2개`

`exposure-structure.prompt:38`의 `(F1 자료 외 사실 금지 우선)`은 전자를 뜻하지만 모델은 구분할 수 없습니다. **참조 ID가 유일하지 않으면 우선순위 선언도, 댕글링 참조 테스트도 성립하지 않습니다.** SECTION 9의 `F1~F15`를 `FP1~FP15`로 개명합니다(외부 참조 3곳은 전부 SECTION -2 쪽을 가리키므로 안전).

## 6. 적용 순서

### 왜 충돌 제거가 먼저인가 — 3가지 이유

1. **측정이 안 됩니다.** 후처리가 매 글에 "실제로 사용해보니"를 넣는 상태에서 프롬프트를 고치면, 결과가 좋아졌는지 나빠졌는지 원인 분리가 불가능합니다.

## 9. 이 규격으로 달성되지 않는 것

**정직하게 씁니다. 아래는 전부 "안 된다"입니다.**

1. **노출·CTR·체류 변화를 측정할 수 없습니다.** 계측기가 고장 상태입니다(전제 8). 이 설계는 어떤 항목에 대해서도 "노출이 오른다"고 주장하지 않습니다. D.I.A.+ 원문의 "18.3%", "50% 이상"은 2020년 네이버 내부 A/B 결과이지 본 앱 산출물에 적용되는 수치가 아닙니다.

2. **"글이 끝판왕으로 나온다"를 이 규격이 보장하지 않습니다.** 규격이 보장하는 것은 **① 층 간 모순 제거 ② 모드 간 중복 제거 ③ 카테고리 파일이 base가 못 하는 말만 하게 되는 것** 세 가지이고, 전부 텍스트 단언으로 검증됩니다. 그 결과 글이 좋아지는지는 **검증 수단이 없습니다.**

3. **저비용 모델(gpt-4.1-mini급)이 어형 구분을 지키는지 미측정.** "-보니는 되고 -해 봤는 안 된다"를 얼마나 지킬지 모릅니다. 못 지키면 `evidenceIntegrity` 하드 실패가 늘고 재생성 과금이 늡니다. **관측 가능한 유일한 지표는 `UNSUPPORTED_FIRST_PERSON` 발생 빈도 로그**이며, R6 배포 후 이걸 봐야 합니다.

4. **`title/` 26파일 충돌은 이번에 해결되지 않습니다.** 제목 프롬프트가 본문 프롬프트와 반대 방향을 지시하는 상태(`결론 차단` vs `답을 숨기지 않는다`, `해봤더니` vs `직접 경험 금지`)가 남습니다. 별건 SPEC.

5. **자카드 재측정값(38%)이 브리프값(41%)과 다른 원인을 단정할 수 없습니다.** 토크나이저 차이로 추정하나 브리프 측 구현을 보지 못했습니다. 방향은 일치합니다.

6. **홈피드 랭킹 파이프라인의 [A] 축자를 확보하지 못했습니다.** NAVER D2 문서가 JS 렌더라 본문 추출에 실패했고, 3자 요약([B])만 확보했습니다. 그래서 **주제 순도는 [B] 근거로만 배치했고, "노출이 오른다"가 아니라 "발표가 스스로 문서측 난점으로 지목했다"까지만 씁니다.** AI 브리핑/AI탭의 인용 문서 선정 기준은 네이버가 공개한 적이 없어 확인 불가입니다.

7. **T4 금칙 사전의 실제 오탐률은 미측정입니다.** 현행 26파일 대상 예상 적발 수만 산출했고, 앞으로 작성될 문장에서의 오탐은 관측되지 않았습니다.

8. **R1(후처리 차단)의 라이브 영향 범위를 모릅니다.** `enhanceEEAT`·`applyAuthGRDefense`는 AI 탐지 회피 목적으로 도입된 코드이고(`contentOptimizer.ts:561` 주석: *"10%는 사람다움 신호가 약해 sterile/AI 느낌"*), 끄면 "AI 티"가 늘어날 가능성이 있습니다. **다만 그 대가로 지금 매 글에 난수 기간이 박힌 거짓 경험이 들어가고 있으므로, 트레이드오프가 아니라 우선순위 문제입니다.** R1 배포 후 실제 글 샘플 육안 확인 필요.
