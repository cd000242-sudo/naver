# PART 1 — 심층 리서치 보고

## 0. 이 보고서를 읽는 규칙 (먼저 읽어주세요)

**출처 표기 원칙.** 아래 [A]/[B]/[C]는 전부 검증팀이 **원문을 직접 열어 문장 단위로 대조**한 것만 실었습니다. URL 문자열이 검증 로그에 그대로 남은 것만 URL을 적었고, 원문 대조는 끝났지만 URL 문자열이 로그에 없는 것은 **문서명 + 게시일 + 발행처**로만 적었습니다. **제가 URL을 지어내지 않기 위해서입니다.** 확인하고 싶으신 항목을 말씀해주시면 그 건만 다시 페치해서 URL을 붙이겠습니다.

**"비밀" 수사를 쓰지 않는 이유.** 요청에 "강사들도 잘 알려주지 않으려 하는 정보"가 있었습니다. 검증 결과를 그대로 말씀드리면 — **그런 건 거의 없었습니다.** 대신 나온 건 세 가지입니다.

1. 강사들이 파는 수치(2000자, 이미지 10장, 좋아요 10개, 발행 시간대)는 **원출처가 없거나 자료끼리 서로 어긋납니다.** 이건 검증됐습니다.
2. 네이버가 **공개적으로 발표해 놓았는데 실무에서 거의 안 읽는 자료**는 실재합니다 (DAN 24 홈피드 발표, 피드메이커 스쿨 교육 내용, 브랜드커넥트 개정 공지). 이게 "잘 안 알려진 정보"의 실체입니다.
3. 네이버 랭킹 알고리즘의 핵심(스마트블록 생성 규칙, 유사문서 임계값, 체류시간 반영 여부, 안전 발행 건수)은 **비공개이며 아무도 모릅니다.** 안다고 파는 사람은 근거가 없습니다.

**그리고 가장 중요한 발견 하나.** 우리 앱의 노출 측정기가 고장 나 있습니다. 그래서 지금까지의 **모든 개선은 효과를 측정한 적이 없습니다.** 이건 아래 §4에서 라이브 재현까지 끝냈습니다.

**② 카테고리 라우팅이 붕괴해 있습니다 — 이게 가장 큽니다.**

- **풀오토/연속발행 경로에서는 카테고리 프롬프트가 단 하나도 로드되지 않습니다.** `fullAutoFlow.ts:2468`이 보내는 `categoryHint`는 영문 슬러그(`celebrity`, `fashion`, `pet`, `it_computer`…)인데 `promptLoader.ts`의 `CATEGORY_MAP`은 한국어 키만 가집니다. UI 슬러그 35개를 `resolveCategory`에 실제로 실행 투입한 결과 **35/35 → `general`**. `general.prompt`는 존재하지 않으므로 **무보정**입니다.
- 세미오토 경로도 UI 36개 옵션 중 **결정적으로 카테고리를 얻는 건 5개뿐**(tips / parenting / shopping_review→life / sports→entertainment / health). `categoryHintMap`에 `travel`·`food`·`entertainment`·`finance` 키가 있는데 **UI가 그 값을 절대 내보내지 않습니다.**
- 나머지는 **키워드 우연**입니다. `sourceAssembler.ts:7431`이 `categoryHint = keywords[0]`을 넣기 때문에, 첫 키워드에 "패션"·"인테리어"·"반려동물"이 들어갈 때만 해당 프롬프트가 붙습니다. **주제가 아니라 키워드 문자열이 프롬프트를 고릅니다.**
- 부분매칭 버그: `'재테크'.includes('테크')` → **`it.prompt`로 오라우팅**(실행 검증). 부동산·세금·절세·금융·투자는 전부 `general`.

### 근거 약한 통설 [C] / 폐기
