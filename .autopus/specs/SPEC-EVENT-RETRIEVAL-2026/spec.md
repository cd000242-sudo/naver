# SPEC-EVENT-RETRIEVAL-2026: 키워드를 검색하지 말고 사건을 찾아라

**Status**: draft / **Created**: 2026-09-10 / **Domain**: CONTENT
**Depends**: SPEC-BLUEPRINT-2026(draft), SPEC-REVIEW-001(완료)
**근거**: `research.md` — 사장님 실측 1건 + 코드 전수 조사

## 목적

황금키워드(검색량은 오는데 문서가 아직 적은 키워드)에서, 자동화가 **주변 자료를 억지로
조립하지 않게** 한다. 두 축으로 나눈다.

- **판정 축**: 같은 낱말을 쓰는 **다른 사건**을 걸러낸다 (지금은 구조적으로 통과한다)
- **쿼리 축**: 자료가 마르면 키워드를 분해해 **중심 사건을 역추적**한다 (지금은 출구가 없다)

## 핵심 통찰

지금 게이트 4곳은 전부 **어휘 겹침**이다. 어휘를 조이면 자료가 마르고, 느슨하면 다른 사건이
들어온다 — 이미 겪었다(`sourceAssembler.ts:8104` 주석). **축을 바꿔야 한다.**

> 사건의 동일성은 낱말이 아니라 **(인물 집합 × 날짜 × 사건 유형)** 으로 정해진다.

송영진 기사는 야구 어휘를 공유하지만 **인물 집합이 겹치지 않는다**. 김영웅 기사는
어휘가 달라도 **인물·날짜가 이어진다**. 이 축이면 둘이 갈린다.

## 요구사항 (EARS)

### Phase 0 — 측정 (코드 변경 없음, 선행 필수)

- M1 WHEN Phase 1 착수 전 → 황금키워드 20~30개로 현재 파이프라인을 돌려
  **자료 부족 비율**과 **곁가지 혼입 비율**을 실측한다. 저장본 재계산으로 하고 유료 재실행은 하지 않는다.
- M2 글 1편당 검색 호출 횟수를 `apiUsageTracker` 로 계측해 기준선을 세운다.
  확장 검색의 비용 배수를 이 값 위에서 계산한다.
- M3 M1 결과로 F2 의 임계(엔티티 2개·문서 3개)를 조정한다. **임계를 먼저 코드에 박지 않는다.**

### Phase 1 — 판정 축: 사건 동일성 (비용 0, 먼저)

- F1 사건 서명(EventSignature) 추출기를 만든다 — **순수 함수**, LLM 호출 없음.
  `{ people: string[], dates: string[], orgs: string[], numbers: string[] }`
  기존 부품을 조립한다: `extractVerifiableClaims`(날짜·기관·수치) + `extractKoreanFactTokens`(인물 후보)
  + `annotateRelativeDates`(상대 날짜 → 절대 날짜).
- F2 WHEN 수집 자료가 2건 이상 → 자료 간 사건 서명을 비교해 **중심 사건**을 정한다.
  중심 사건 = 인물·날짜가 가장 많이 겹치는 자료 묶음.
- F3 WHEN 어떤 자료의 사건 서명이 중심 사건과 **인물 0명·날짜 0개 겹침** → 본문 재료에서 제외한다.
  이 규칙 하나가 송영진을 뺀다.
- F4 F3 는 **버리지 않고 강등**한다 — 설계도(Blueprint)의 `offTopic[]` 으로 넘겨
  "본문에서 제외할 재료 주제"로 명시한다. 자료가 마르는 쪽으로 기울지 않게 한다.
- F5 제외 판정은 **로그에 이유를 남긴다**: 어떤 자료가 어떤 인물·날짜 불일치로 강등됐는지.
  근거 없는 제외는 진단이 불가능하다.
- F6 기존 게이트 4곳(`isOnTopicForKeyword`)은 **그대로 둔다**. 사건 서명은 그 뒤에 얹는 층이다.

### Phase 2 — 쿼리 축: 자료 부족 감지 + 확장 검색 (비용 증가)

- F7 자료 부족 판정: WHEN 상위 N개 문서 중 **키워드의 주요 엔티티 2개 이상을 동시에 포함한
  문서가 K개 미만** → `자료 부족 키워드`로 판정한다. N·K 는 Phase 0(M3) 결과로 정한다.
- F8 WHEN 자료 부족 판정 → 키워드를 엔티티 단위로 분해해 2차 질의를 만든다.
  `김서현 류현진 평행이론` → `김서현 류현진` / `김서현 플레이오프` / `류현진 플레이오프` …
  분해는 **키워드 안의 엔티티 조합만** 쓴다 — 바깥 낱말을 새로 지어내지 않는다
  (`contentGeneration.ts:1149` "다른 키워드 사용 금지" 결정을 이 범위로 한정 완화).
- F9 2차 질의 결과에서 **다리 엔티티**를 찾는다 — 원래 키워드에는 없는데 여러 문서에
  공통으로 등장하는 인물·날짜. 실측 사례의 `김영웅` 이 이것이다.
- F10 다리 엔티티로 3차 질의를 1회만 던진다. **깊이는 3차에서 끝낸다** — 무한 확장 금지.
- F11 확장 검색 총 호출 상한은 설정값으로 두고 기본값을 Phase 0 기준선의 **N배 이내**로 둔다
  (구체값은 사장님 승인 필요). 상한 초과 시 있는 자료로 진행한다.
- F12 WHEN 확장 검색으로도 중심 사건을 못 찾음 → **글을 막지 않는다.**
  있는 자료로 쓰되 F3 배제 규칙은 그대로 걸고, 설계도 `angle` 을 좁힌다.
  (막으면 "왜 글이 안 나오냐"가 되고, 억지 조립만 막으면 짧아도 말이 되는 글은 나온다)
- F13 확장 검색은 **옵트인 설정**(`expandedRetrieval`, 기본값 사장님 결정)으로 켜고 끈다.
  일반 키워드는 종전 경로 그대로 — 비용이 새지 않게 한다.

### 공통 제약

- C1 하드코딩된 모델·키 없음. 보조 LLM 호출이 필요하면 `resolveSelectedEngineRoute` 로 간다.
- C2 자동 폴백 없음. 확장 검색 실패는 단계 생략이지 엔진 교체가 아니다.
- C3 게이트를 **발행 차단으로 만들지 않는다**. 경고·강등까지가 이 SPEC 의 권한이다.
- C4 파일 300줄 상한. 사건 서명 추출기는 새 파일로 분리한다.
- C5 크롤 예산(20초)은 Phase 2 에서 재산정한다 — 질의가 늘면 편당 시간이 늘어난다.

## 비범위

- 일반 키워드의 수집 경로 변경.
- 쇼핑(affiliate)·업체(business) 모드.
