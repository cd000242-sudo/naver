# SPEC-BLUEPRINT-2026: 설계도 선행 생성 — 첫 호출에서 노출급 형태
**Status**: draft / **Created**: 2026-09-04 / **Domain**: CONTENT
**Depends**: SPEC-HOMEFEED-EMPATHY-2026, SPEC-REVIEW-001, 하네스 P29(품질 보정 기본 ON)

## 목적
홈판·SEO 글이 첫 본문 호출에서 노출급 형태(독자 상황으로 시작하는 도입부, 당사자 직접 인용, 근거 붙은 사실, 곁가지 없는 재료)로 나오게 하여 게이트 재생성·패치 발화율을 낮춘다. 비용과 시간을 함께 낮춘다.

## 요구사항 (EARS)
- F1 WHEN 홈판·SEO 글 생성(키워드·URL 모두) → 본문 호출 전에 설계도(Blueprint) JSON 을 1회 생성한다.
  필드: `readerSituation`(1문장) · `quotes[≤5]`({text: 재료 원문 그대로, speaker}) · `facts[≤8]`({claim, snippet: 재료 발췌}) · `skeleton[3~6]`(소제목 후보, 서로 다른 질의 축) · `offTopic[]`(본문에서 제외할 재료 주제) · `angle`(이 글이 답할 한 질문).
- F2 설계도 호출은 고른 엔진의 보조 라우트(`resolveSelectedEngineRoute`)로 간다. 에이전트 엔진은 기본 생략(봉투가 내부 분석을 수행) — 설정으로 켤 수 있다.
- F3 WHEN 설계도 확보 → 본문 프롬프트의 재료 블록을 "설계도 + facts 의 원문 발췌"로 구성한다. 원문 통째 주입은 하지 않는다. 목표 프롬프트 길이 ≤ 35,000자.
- F4 스키마 필드 바인딩: `introduction` 은 `readerSituation` 에서 출발해야 한다(코드 검증, 미달 시 기존 도입부 패치 1회). `quotes` 는 본문에 글자 단위로 포함되어야 한다(재료 인용 ≥3 일 때 ≥2). 미달 시 재생성 대신 삽입 보정(짧은 호출 1회).
- F5 WHEN 설계도 호출 실패·타임아웃(20초)·파싱 실패 → 현재 경로(원문 주입)로 진행하고 로그를 남긴다. 엔진은 바꾸지 않는다(단계 생략일 뿐 폴백 아님).
- F6 게이트·재생성·자기비평은 그대로 둔다(보험). 설계도 유무·발화율·프롬프트 길이를 로그에 남겨 효과를 잰다.
- F7 쇼핑(affiliate)·업체(business)는 이번 범위 밖 — 기존 경로 그대로.
- F8 설정 `blueprintStage`(기본 ON) 로 끌 수 있다. 하드코딩된 모델·키 없음.

## 비기능
- 비용: 설계도 호출 ≤ 본문 호출의 10%(입력 ≤30K자, 출력 ≤1.5K자, 그 벤더 저비용 티어). 통과 글 추가 비용 0 유지.
- 시간: API 엔진 +5~20초. 에이전트 엔진 기본 +0.
- 코드: 새 모듈 각 ≤300줄, 순수 함수 우선(프롬프트 조립·파싱·검증은 네트워크 없이 테스트). god file 배선은 최소 3~4줄, 기존 계약 테스트(finalize 반환 핀·V3 wiring·지문·베이스라인) 유지.
- 안전: facts 는 재료 발췌를 동봉해 조작 검사·근거 정합성 검사를 그대로 통과해야 한다. 설계도가 만든 문장을 사실로 쓰지 않는다.

## 범위 밖
- 소제목 문체(홈판 서술형 허용 계약) 변경, 감정 키워드 환각 휴리스틱 수정(별건), 엔진 추가.
