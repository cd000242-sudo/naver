## 1. 배경

소제목 이미지는 쓸 만하지만 홈판·피드용 썸네일 품질이 부족하다. 사장님이 짚은 실패:

- 실존 인물 기사인데 전혀 다른 AI 모델이 나온다
- 기사 맥락 대신 AI가 임의 상황극을 만든다
- 썸네일에 제목 전체가 긴 텍스트로 들어간다
- 작은 홈판 카드에서 무슨 글인지 알기 어렵다
- 실제 이미지가 있어도 AI 생성부터 시작한다
- 소제목 이미지에 영화 같은 연출과 AI 티가 남는다
- 사람과 구도가 반복된다
- 가로형·포스터형으로 생각한다

코드 조사로 확인한 뿌리:

1. 소제목 프롬프트는 소제목마다 따로 만들어져 형제 소제목을 모른다. 다양성 수단은 카메라 각도 회전 하나뿐이었다.
2. 이미지 탭 썸네일은 칸 이름 "🖼️ 썸네일"을 번역한 문장으로 만들어졌다. 제목이 표지를 이끌지 못했다.
3. 썸네일에 글자를 얹는 살아 있는 경로 세 곳(생성 때 오버레이, 발행 때 오버레이, 상품 썸네일 IPC)이 모두 제목 전체를 썼다. 글자를 직접 그리는 엔진에는 어떤 글자를 쓸지 지정하지 않아 제목 전체를 그리기 쉬웠다.
4. 실제 사진이 본문에 있어도 썸네일은 항상 AI 생성으로 시작했다.

## 2. 범위

포함: 이미지 관련 코드, 프롬프트, 문서, 테스트.

제외(V1 §29): 빌드, 릴리스, 배포, 글쓰기 엔진(Search/Packet/Writer/Critic/Editor/Quality Loop), 제목 엔진, ORBIT Quality Loop, 유료 이미지 대량 호출.

## 4. 설계 원칙

- 선택 단계는 결과를 부수지 않는다. 합성·심사·카드가 실패하면 기존과 같은 1장을 쓴다.
- 발행을 막는 게이트를 새로 만들지 않는다. 품질 검사는 기록과 안내만 한다.
- 자동 폴백 없음. 심사 엔진은 사용자가 고른 글 엔진의 가장 싼 비전 모델이다. 없으면 심사를 건너뛴다.
- 결정적 우선. 역할 배정, 문구, 품질 검사는 규칙 기반이라 추가 비용이 0이다.
- 브리프 모듈(contextualImagePrompt)은 렌더러 번들에 인라인되므로 import를 추가하지 않는다. 역할과 문구는 문자열로 받는다.
