## 1. 목표

키워드·예약시간·글쓰기 모드만 정해 두면, 사람이 제목·본문·이미지를 다시 고치지 않아도
각 글이 선택한 모드대로 써지고, 썸네일 1 + 최종 H2당 1장의 홈판용(800x800) 이미지가 붙고,
필수 이미지가 갖춰진 글만 예약 시각에 자동 발행되는 운영 시스템.

## 2. 핵심 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | 글쓰기 모드(contentMode)와 이미지 전략(imageStrategy)은 별개 변수다. 이미지 코어는 contentMode 를 입력으로 받지 않는다 | 지시 §1·§2·§31 |
| D2 | 완전자동 이미지 기본 전략 = 홈판/피드 최적화: 1:1 요청 + 800x800 강제, 썸네일 항상 1장, 소제목 범위 기본 전체, 썸네일 문구 AUTO, 실제 사진 우선·2장 합성 | 지시 §2 |
| D3 | 사용자가 전략을 "내 이미지 설정 그대로"로 바꾸면 기존 비율·썸네일 텍스트 체크박스를 따른다 | 지시 §2 마지막 줄 |
| D4 | 예약 큐 항목은 큐에 넣는 순간 이미지 전략·소제목 범위·썸네일 문구를 고정한다. 새 항목 기본 범위 = 전체 | 지시 §14 "예전 설정이 조용히 이어지지 않게" |
| D5 | 이미지 슬롯은 사용자가 보는 1-based H2 번호로 키를 잡는다. 실패한 칸은 비워 두고 뒤 이미지가 밀려 들어오지 않는다 | 지시 §16 |
| D6 | 발행 판단: CONTENT_READY + IMAGE_READY = AUTO_PUBLISH. 썸네일 실패, 범위 안 H2 이미지 누락, 선택 엔진이 아닌 모델로 만들어진 이미지, 이미지 생성 뒤 바뀐 소제목 → IMAGE_REVIEW_REQUIRED(발행 안 함, 글·성공 이미지 저장) | 지시 §15·§17·§18 |
| D7 | 이 판단은 무인 실행(원클릭 풀오토·예약 큐·다중계정)에만 적용한다. 반자동(사장님이 보며 큐레이션)은 그대로 | 기존 결정 "라이브 발행=사용자 큐레이션 신뢰" |
| D8 | 글 품질 판정은 기존 그대로. 새 유료 심사·새 provider·기본 장수 증가 없음 | 지시 §31 |
| D9 | 네이버 서버 예약이 이미 "미리 완성 → 예약 시각 발행" 구조라 별도 pre-generation 은 만들지 않는다 | 감사 결과, 지시 §20 "무리하게 갈아엎지 말 것" |

## 3. 기존 결정과의 관계 (사장님 확인 권장)

- V1(SPEC-NAVER-IMAGE-2026 §4)의 "발행을 막는 게이트를 새로 만들지 않는다"와 이번 지시 §18("썸네일 실패: AUTO_PUBLISH 금지")이 부딪힌다. 이번 지시가 최신이라 따르되, 판단 재료를 **생성 결과의 결정적 상태**(슬롯·크기·추적 정보)로만 한정했다. 에디터 입력 뒤 개수 비교(PrePublish 70% 규칙)는 건드리지 않았다.
- 예약 큐의 이미지 연속 실패 차단기는 "시도"가 아니라 "글" 단위로 센다. 이미지가 한 장도 안 나온 글이 2편 연속이면(엔진 자체 장애) 기존처럼 큐를 멈춘다.
